# 🚀 November 2026: A Coming Soon Teaser

**Welcome to the Technical Department!** 
For your first task, we are going back to the basics of the CSS web development stack. Before we build complex event platforms like VHACK or PIXEL, we need to understand our core meta-framework (Astro) and how we get our code live on the internet. 

Your goal this month is to build and deploy a static "Coming Soon" teaser website for a fictional upcoming society event.

## 🎯 Objectives
- Understand basic Git and GitHub workflows.
- Learn Astro project structure, routing, and layouts.
- Experience the CI/CD pipeline by deploying automatically to Cloudflare Pages.

## 🛠️ Prerequisites
-  Node.js installed on your machine.
-  Git installed and configured.
-  A GitHub account.
-  A Cloudflare account (you can sign up for free).

---

## 📝 Task Instructions

### Step 1: Project Setup & Version Control
1. Fork this repository
2. Clone the forked repository to your local machine
3. Inside the cloned repo folder, initialize your new Astro project using the terminal command: `npm create astro@latest .` (Choose the "Empty" template).

### Step 2: Building the UI & Routing
Astro is fantastic for static sites. We want to utilize its layout system to keep our code DRY (Don't Repeat Yourself).
1. **Layouts:** Create a `src/layouts/BaseLayout.astro` file. This should contain your HTML boilerplate, a simple Navigation Bar, and a Footer.
2. **Pages:** Use your `BaseLayout` to create the following pages in the `src/pages/` directory:
   - `index.astro`: The landing page with a catchy title, a short description of the mock event, and a "Coming Soon" message.
   - `about.astro`: A page explaining what the event is about (get creative!).
   - `404.astro`: A custom error page with a button to return to the homepage.
3. **Styling:** You can use plain CSS in the `<style>` tags of your Astro components, but it's recommended to install TailwindCSS.

### Step 3: Deployment (The CSS Way)
We use Cloudflare Pages to host our event sites because it is fast and integrates perfectly with GitHub.
1. Commit your changes and push your branch to your forked remote repository.
2. Open a Pull Request (PR) from your repo to the original USM CSS repo. 
3. Log into Cloudflare, go to **Workers & Pages** -> **Create application** -> **Pages** -> **Connect to Git**.
4. Select your forked repository.
5. Set the framework preset to **Astro** (this will auto-fill the build command as `npm run build` and output directory as `dist`).
6. Deploy!

## 🏆 Success Metrics (Definition of Done)
To complete this month's task, you must have the following in the PR made to the original repo:
-  The live `https://<your-project-name>.pages.dev` URL generated by Cloudflare.
-  The live website must have working navigation between the Home and About pages.
-  Navigating to a random URL (e.g., `/does-not-exist`) must show your custom 404 page.
